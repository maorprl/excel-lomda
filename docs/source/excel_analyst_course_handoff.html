3 Protocol 1 — Course Workbook Architecture & Pedagogy

Core architecture: One capability module = one Excel Workbook. One learning topic = one Worksheet / tab.

Workbook Structure

  • כל Module הוא קובץ .xlsx אחד.
  • כל נושא לימודי הוא Worksheet נפרד.
  • כל Worksheet הוא שיעור/תרגיל עצמאי עם מטרה אנליטית אחת ראשית.
  • שמות הלשוניות צריכים להיות מסודרים, קצרים ותיאוריים, למשל: 01_DUPLICATES, 02_MISSING_VALUES, 03_TEXT_CLEANING.
  • ה־Workbook צריך להרגיש כמו קורס אנליסטים עקבי, לא כמו אוסף datasets אקראיים.

Pedagogical Model

Principle
Do not reveal the lesson at the beginning. ה־Worksheet צריך לאפשר ללומד להיתקל בבעיה, לבדוק אותה, לאסוף evidence ורק אז לנסח את העיקרון.

Every Worksheet Should Contain

  • Short business / analyst context.
  • Realistic source data.
  • One primary concept.
  • Purposeful but subtle traps/evidence.
  • Usually 4–7 discovery questions.
  • Enough information to solve the task directly in Excel.
  • No visible solutions and no obvious highlighting of the hidden issue.

Question Progression

  1. Observation: What do you see?
  2. Verification: How can you test it?
  3. Evidence: What proves the conclusion?
  4. Impact: Why does it matter analytically?
  5. Professional behavior: What would you check before trusting or changing the data?

Cumulative Learning

Data Discovery

Which field appears to be the identifier?

Data Cleaning

Does that identifier actually behave as a unique key?

Lookup / Join

Is that key safe to use in a relationship?

Principle: Modules must build on prior mental models instead of restarting from zero.

Language Rules

  • Chat explanations: Hebrew.
  • Excel functions, menu names, formulas and technical terms: English.
  • Workbook content, datasets and questions: English.

4 Protocol 2 — Practice Workbook / Dataset Generation & Interview Realism

General Rules

  • Build real .xlsx practice workbooks, not screenshots or pseudo-tables, whenever hands-on work is useful.
  • The workbook is for independent practice, not a solved example.
  • Do not include solutions, answer sheets, completed formulas or obvious hints unless explicitly requested.
  • Prefer realistic analyst domains: orders, customers, products, regions, status, dates, revenue, cost, etc.
  • Data size should be manageable but meaningful — enough rows for patterns to exist and for mistakes not to be immediately obvious.
  • Preserve clear row grain and intentional relationships.

Purpose-built Data

Every irregularity must teach something. Do not add random bad data just to make the workbook “harder”.

Grain and Relationships

ה־dataset חייב לשמור על grain הגיוני. לדוגמה:

One row = one order line

Line_ID      → row-level identifier
Order_ID     → may repeat
Customer_ID  → may repeat
Product_ID   → may repeat

כאשר נדרשים joins, השתמש בטבלאות נפרדות:

Sales.Product_ID   → Products.Product_ID
Sales.Customer_ID  → Customers.Customer_ID

כאשר הנושא הוא key integrity, אפשר להכניס בכוונה בעיה ממוקדת כגון duplicate lookup key, blank foreign key או unmatched key — אבל לא להפוך את כל הנתונים לשבורים.

Module-specific Dataset Design

ModuleDataset behavior
Data Cleaning Controlled duplicates, blanks, inconsistent labels, spaces, text-numbers, text-dates, invalid or suspicious values.
Row-level Calculations Raw inputs such as Units, Unit_Price, Unit_Cost, Discount; derived columns left blank for the learner.
Conditional Logic Enough row combinations to exercise every branch of IF/IFS-type business rules.
Aggregation Repeated dimensions and multiple rows per group so SUMIFS/COUNTIFS/Pivot-style summaries are meaningful.
Lookup / Join Multiple related tables with intentional 1:M relationships and validation opportunities.
PivotTables Rich flat data spanning dates, products, regions and measures; prefer real PivotTable practice.
Business Analysis Enough variation for top/bottom, trend, segment, profitability and interpretation questions.

Interview Realism & Question Design

Hard rule: Do not design the worksheet around an Excel function. Design it around an analyst problem.

כל Worksheet צריך לדמות מצב אמיתי של Data Analyst interview, Excel take-home assignment או חקירה של Workbook שקיבלת ממישהו אחר. השאלות צריכות לבדוק reasoning והתנהגות מקצועית — לא שינון פונקציות.

Question Design

כל Worksheet יכיל בדרך כלל 4–7 שאלות, המתקדמות דרך כמה שכבות:

  1. Discovery: What do you notice about the data or workbook?
  2. Verification: How would you prove whether that observation is true?
  3. Analytical Risk: Could this issue change a count, total, join, KPI, or conclusion?
  4. Excel Investigation: Which Excel tool, formula behavior, or workbook feature would you inspect?
  5. Professional Judgment: What would you do before editing, cleaning, joining, refreshing, or presenting?
  6. Communication: When appropriate, explain the finding as if reporting it to a manager or interviewer.

Interview-style Traps

יש לשלב מלכודות ריאליסטיות הדומות למה שאנליסט עלול לפספס תחת לחץ זמן. המלכודת צריכה להיות סבירה, לא puzzle מלאכותי.

  • A candidate key that looks unique but contains one duplicate.
  • A valid formula that stops before the final source row.
  • A numeric-looking value stored as text.
  • An inconsistent category label that splits one logical group.
  • A hidden row that still belongs to the requested business population.
  • A lookup key that exists on one side but not the other.
  • A KPI that is mathematically correct today but hardcoded.
  • Stale refresh evidence or inconsistent freshness clues.
  • An ambiguous business question with no defined metric.
  • A repeated Order_ID where the true grain is order-line level.
Traps must be plausible. The learner should be able to detect them using normal Excel inspection, analytical reasoning and validation — not by guessing what the course designer hid.

Question Wording

Prefer realistic prompts:

Can this field safely be used as a unique identifier?

What would you verify before using this table in a lookup?

Would you trust the displayed total? Why or why not?

What evidence suggests the workbook may not be fully refreshed?

Which records would be excluded if you analyzed only what is visible?

Avoid textbook prompts such as:

Use COUNTIF to find duplicates.

ה־capability הוא מה שנבחן. הפונקציה או הכלי המתאימים צריכים לצמוח מתוך הבעיה, ולא להיות מוכתבים מראש אלא אם זה חלק מפורש מההערכה.

Assessment Mindset

לכל Worksheet צריכה להיות שאלה סמויה מצד המראיין:

“What professional capability would an interviewer learn about the candidate from this task?”

דוגמאות למה שהתרגיל עשוי לבדוק:

  • Attention to grain.
  • Data-quality skepticism.
  • Formula auditing.
  • Validation habits.
  • Key integrity.
  • Business-definition awareness.
  • Ability to distinguish evidence from assumptions.

אין לתגמל רק הגעה למספר הנכון. פתרון חזק צריך גם להדגים:

  • Correct reasoning.
  • Correct population / grain.
  • Auditability.
  • Appropriate validation.
  • Awareness of risks and assumptions.

Excel = practice environment.
HTML = permanent learning summary created only after the worksheet is completed.

Do not create the chapter before the exercise is completed.

Required Chapter Content

  • Course chapter title and original worksheet/tab name.
  • Short analytical/business context.
  • Relevant source data or representative table.
  • Original exercise questions.
  • Final answer to every question.
  • How do we know? for important conclusions.
  • Excel evidence and relevant formulas.
  • Exact Excel menu/tool paths when useful.
  • Visual flows / comparison cards for tricky logic.
  • Common mistakes and confusing distinctions.
  • Validation / reconciliation where relevant.

Real vs Simulated Evidence

אם worksheet מדגים משהו שאינו object חי ב־Excel, חובה לומר זאת במפורש. לדוגמה: snapshot שמדמה PivotTable, hardcoded refresh clue, historical formula evidence, או text שמתאר query.

Never imply that a live Excel object exists when the exercise only contains simulated or recorded evidence.

Visual Style

  • Static HTML — not a quiz app, dashboard or learning product.
  • RTL Hebrew layout.
  • Light background, white card sections, blue accent.
  • Rounded borders, subtle shadows, clear callouts.
  • Responsive and print-friendly.
  • Data tables and formulas LTR where appropriate.
  • Consistent design across all chapters and modules.

Naming & Numbering

Course numbering is sequential and independent of original workbook exercise numbers.

chapter_01_duplicates_summary.html
chapter_02_missing_values_summary.html
chapter_03_data_types_summary.html

Inside the page, preserve the original worksheet reference when relevant:

Course Chapter 03
Original Worksheet: 05_DATA_TYPES

Module Master HTML

After the module is complete:

  • Combine every completed chapter into one full Module Master HTML.
  • Do not replace chapters with short summaries; preserve the full content.
  • Add Table of Contents, Previous / Next and Back to Contents navigation.
  • Keep both the individual chapter HTML files and the combined Master.

7 הוראות התחלה למודול הבא — Data Cleaning

Transition:
Data Discovery asked: “What is in this workbook, and how is it structured?”
Data Cleaning asks: “Can I trust the actual values inside that structure?”

Build a New Module Workbook

המודול הבא צריך להיות Workbook חדש ומסודר, שבו כל נושא הוא Worksheet נפרד. אל תסתפק ב־Exercise 13 ו־16 בלבד; אפשר להשתמש בהם כהשראה / anchor, אך המטרה היא לבנות מודול שלם לפי הפדגוגיה שהוגדרה כאן.

Recommended Starting Architecture

01_DUPLICATES
02_MISSING_VALUES
03_TEXT_CLEANING
04_INCONSISTENT_LABELS
05_DATA_TYPES

זו ארכיטקטורת פתיחה מומלצת, לא חובה קשיחה. אפשר לשנות את מספר הלשוניות אם יש הצדקה פדגוגית, אך חייבים לשמור על topic-per-tab, progression ו־cumulative learning.

Pedagogical Bridge from Data Discovery

Earlier

Which column appears to be the row identifier?

Now

Does that identifier actually behave as a unique key?

Key transition:
עד עכשיו בדקנו אם ה־Workbook בנוי נכון.
עכשיו מתחילים לבדוק אם ה־data שבתוכו מתנהג נכון.

Data Cleaning Topics Should Teach

  • Duplicate detection and key behavior.
  • Missing values and analytical impact.
  • Whitespace / text normalization.
  • Inconsistent labels and category fragmentation.
  • Underlying data types: dates, numbers, percentages, booleans, codes.
  • Quality scan before analysis.
  • Capstone combining several issues without obvious labels.

Important Design Rule

Do not write “this worksheet contains a duplicate / text-number / bad date”. Let the learner discover the issue through the questions and Excel evidence.
